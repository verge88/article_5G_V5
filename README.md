# Иерархический мониторинг 5G Core с КИЕ

Эксперимент использует **реальный Open5GS v2.7.5**, закреплённый на коммите
`7dfd9a39649700c24c22f1978ed7a35541a72cca`. Его штатный тестовый клиент
выполняет NAS/NGAP регистрацию и создание сессий через настоящие процессы
AMF, SMF, AUSF, UDM, UDR, PCF, NRF и SCP. Радиоканал и коммерческие UE не моделируются.

КИЕ — экспериментальное расширение HTTP/2-сервера Open5GS. Оно работает
по маршруту ведущий → SCP → NF на том же SBI-порту, что и обычный обмен.
Это не стандартный heartbeat NRF и не стандартизованный API 3GPP.
Проверяемая NF возвращает счётчики и время обслуживания с HMAC-SHA256,
номером опроса и nonce. Отдельная инструментальная точка в процессе SCP
записывает реально выполненные HTTP/2-обмены независимо от отчётов NF.

Контролируемые воздействия изменяют отчётность лабораторной NF до её
аутентификации. Это проверка обнаружения недостоверной отчётности, а не
воспроизведение эксплуатации уязвимостей и не доказательство выявления
произвольной компрометации. Ключи эфемерные, лабораторные; данный патч
не предназначен для эксплуатации в сети оператора.

GitHub Actions `Open5GS integration` собирает ядро из исходников и сохраняет
журналы процессов, независимые наблюдения SCP, исходные КИЕ, сценарии и
контрольные суммы в артефакте. При отказе ядра или отсутствии измерений
запуск завершается ошибкой; синтетическая подмена данных отсутствует.

## Локальный запуск на Ubuntu 22.04

Нужны MongoDB на `127.0.0.1:27017`, Python 3.12 и право создать TUN.

```bash
pip install -r requirements.txt
bash lab/install_dependencies.sh
bash lab/build.sh
python -m experiment.collect --config configs/smoke.json --seed 11 --output results/seed-11
```

Исходная методика запуска ядра:
[официальная документация Open5GS](https://open5gs.org/open5gs/docs/guide/02-building-open5gs-from-sources/).
Наличие GitHub Actions и успешных тестов само по себе не подтверждает научную новизну.
